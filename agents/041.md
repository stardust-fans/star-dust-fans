# 歌曲分页搜索与可选标签：决策依据

- 分页覆盖歌曲公开页和歌曲管理页；原请求把分页与歌曲搜索放在一起，其他内容列表保留本次范围之外。
- 在 D1 先过滤和排序，再分页，并以相同过滤条件计数，确保可搜索整库并避免按局部页排序。
- 沿用项目现有数组响应与独立计数接口；复用参数过滤和前端分页状态，不增添迁移、兼容层或依赖。
- 首页只需要最新六首，无须预取整个曲库。公开列表每页十二首，后台每页二十首。
- 标签原本支持空值；补充可选文案与保存验证，不重复新增必填逻辑。
- 管理列表包含隐藏和标记歌曲，须经过管理身份验证；换曲时重建表单并返回标记原因，保证编辑数据完整。
- 用接口测试验证全库查询、计数、权限与无标签保存；用 Vue 公共渲染 API 和 Vitest 验证异步响应顺序、删除末页与重试行为，浏览器另验交互和布局。
- 纯前端状态测试使用 Vitest Node 项目，接口与 schema 测试保留 Cloudflare 项目，避免让不依赖 D1 的状态测试也启动 Worker 运行时。
- 浏览器 elementsFromPoint 确认 Live2D 画布位于下一页按钮之上。分页层高于装饰角色；在组件原本跳过加载的窄屏上隐藏其空白容器，保证新操作可点击，不改变角色模型和动作实现。
- 原歌曲 DELETE 标记 status=deleted。管理分页包含可编辑的非公开歌曲，但列表和计数应排除已删除记录；不增加回收站或更改删除接口。
