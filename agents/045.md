# 多权限组授权决策

- 用户要求可组合权限组、read/write 动作级权限，以及前后端入口和接口拒绝。
- 沿用 ADMIN_ACCOUNTS Secret，统一存储 groups 定义和 accounts.groupIds；有效权限为多组并集。删除 role 和账号直接 permissions，不保留旧格式 fallback。
- 每个模块 write 包含同模块 read；manage 只管理账号和权限组，不隐含其他内容权限。
- 至少一个现存账号拥有 manage:write，避免成员调整、删除账号或修改组导致管理能力丢失。无权限身份不能访问任何管理接口；公共内容仍按原公开契约访问。
- 继续更新现有草稿 PR，保留生产 Secret 配置就绪的发布前提。

- 新增用户要求：check workflow 默认只报告明显性能劣化。准备以已合并 main 的成功测试报告作基线，保留 Checks 红绿状态及敏感路径评审请求，正常运行不发表评论。无基线时跳过性能结论。

- 用户进一步确认默认缩略评论，并检查SQL与代码的明确问题。采用现有Vue编译器的JS解析与Node内置SQLite EXPLAIN QUERY PLAN，不新增依赖、不执行被检查SQL。已有D1双引号字符串语义按实际配置启用。
- 性能只比较同一已存在测试/SQL：单测试3倍且+250ms，或匹配测试总耗时翻倍且+1s；SQL只报告原索引检索变全表扫描，无基线不作结论。
