# 调查与决策

- [OMEW 报 `SSO_USERNAME_INVALID`] -> [核对主站 OIDC claims 和 OMEW localpart 规则] -> [主站原样发出 users.username；OMEW 内部 localpart 限制为 2–32 位小写英数字、下划线或短横线。OMEW 兼容修复已部署，但 Rosmontis 要求主站也统一规则。]
- [不确定受影响账号] -> [只读查询主站 OIDC token 和用户名分布] -> [34 个生产账号中 26 个不符规则；近期唯一不符账号的 OMEW token 对应用户 ID 34。直接更名所有账号会影响多数用户，必须保留原有公开称呼和通过注册邮箱登录的路径。]
- [存量用户名处理] -> [核对 26 个名字与 `user_<id>` 候选的唯一性] -> [候选在生产库中无冲突，迁移可按稳定数字 ID 生成，不把真实名字写入代码。邮箱式旧用户名不应继续作为公开显示名。]
- [会话边界] -> [核对 JWT、cookie 与 OIDC 实现] -> [已有 JWT 含旧 username，但鉴权依据 sub；OIDC 授权按 sub 重新读取用户行。服务端需要以当前数据库用户名覆盖旧 claim，前端需刷新展示信息。]
- [大小写边界] -> [只读检查生产库] -> [另有 5 个 ASCII 用户名只因大写与目标存储规则不同；小写化后无碰撞。保留原拼写作显示名，登录名统一小写。]
- [论坛现有身份] -> [只读查询 OMEW oidc_identities] -> [现有 2 个 subject 为主站 ID 2、31，均不在 26 个特殊字符账号中；迁移不会改变已有论坛 actor。]
- [字段契约] -> [采用 users.username 为 2–32 位小写 ASCII 登录名，users.display_name 为可空公开称呼；空值回退 username。26 个特殊字符名字分配 `user_<id>`，其中邮箱式旧名字不继续公开，其他旧称呼保存在 display_name；5 个大小写名字存小写登录名与原样显示名。OIDC preferred_username 使用登录名，name 使用显示名。]
- [可达性] -> [改名后旧用户名不能再登录] -> [登录入口允许注册邮箱作为标识，用户中心显示新登录名；不按旧用户名建立兼容别名。]
- [整套历史迁移在新本地 D1 上停止] -> [检查失败输出] -> [首个历史迁移需要预先存在的 `songs` 基础表，空库缺表；随后在隔离本地 D1 中按旧 users 结构执行本次迁移，四条代表性记录结果全部符合预期。]
- [生产迁移预演] -> [只读导入 34 条 ID/用户名到内存 SQLite 并执行新迁移] -> [31 个登录名更新（26 个特殊字符、5 个大小写），29 个公开称呼保留、2 个邮箱式称呼改为新登录名；0 冲突，全部符合 2–32 位 ASCII 规则。]
- [邮箱登录歧义] -> [生产库只读查询 lower(email) 重复组] -> [0 组；代码在查询结果不唯一时拒绝登录，不会猜选账号。]
- [受保护主线自动交付顺序] -> [检查 ruleset 与 Auto Merge 工作流] -> [PR 通过检查后先迁移再部署并合并；账号更名必须独立于新增列/兼容代码的首次发布，以免部署失败后旧 Worker 遇到已更名数据。]
- [阶段一旧名登录] -> [检查 5 个混合大小写和含 ASCII 大写的中文名] -> [登录查询改用 NOCASE，并在不唯一时拒绝；生产 username 忽略大小写后无歧义，阶段一仍可输入旧名。]
- [分阶段迁移验证] -> [隔离本地 D1 依次运行新增列与账号更名 SQL] -> [第一阶段四条旧名全部保持，第二阶段得到预期 ASCII 登录名和显示名。]
- [第一阶段线上验证] -> [核对 PR #75 自动交付与生产 D1] -> [构建、恢复点、迁移、Worker 部署和合并均完成；`display_name` 列已存在、旧名仍保持，线上注册拒绝不符 ASCII 规则的新用户名。未持有用户凭据，邮箱登录与真实论坛回调仍属代码和自动测试覆盖。]
